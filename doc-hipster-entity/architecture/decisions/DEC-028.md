# DEC-028: Metadata addresses source files through a central index, and a field carries all its locations

- Owners: project

## Context

Two observables in the generator's metadata JSON, both about *where a field is*, made the
DEC-027 amendment's shape untenable at the size the example module reaches:

1. **A path is repeated once per location.** The metadata named source files by their full
   module-relative path — 83 characters on average in this repository — and a field has many
   locations, so the same 30 paths were written hundreds of times. On the rendered page, the
   measured identity payload was 420 locations naming 30 distinct files, 34 851 characters of
   path text where the same 30 paths written once cost 2 459.
2. **Only one of a field's locations was recorded at all.** A field carried `sourcePath` +
   `lineNumber`: the *declaration start* in the declaring interface, annotations included. The
   constant in the generated field enum, the record component, the field and setter in each
   builder, the ordinal switch arm and the name lookup were **not** in the metadata. The HTML
   page reconstructed them at render time by scanning the committed source and guessing by
   naming convention — so no consumer other than that one renderer could answer "where is this
   field", and the page's correctness rested on a line heuristic rather than on the pass that
   wrote the files. The heuristic was not merely approximate; it was wrong. The scan recognised
   an enum constant with `/^\s*([A-Za-z_$][\w$]*)\s*\(/`, which does not match a constant the
   emitter writes as `, email(java.lang.String.class) {` (the comma on the same line), so the
   ledger for three views was truncated.

The plan that closed both defects is `plans__p1/plan.metadata-locations.md`. This decision
records the contract it produced; the plan is the specification and this document is the
decision, in the same relationship DEC-027 has to its own plan.

## Decision

### 1. The index is central and per module: `.jcodebuddy/index/files.json`

A pass writes **one** addressing table for the whole module, beside the documents that
reference it:

```jsonc
// <module>/.jcodebuddy/index/files.json
{
  "format": 1,
  "module": "hipster-entity-example",
  "sourceRoot": "src/main/java",
  "files": {
    "entity.Person": "src/main/java/hr/hrg/hipster/entityexample/person/entity/Person.java",
    "iface.Person":  "src/main/java/hr/hrg/hipster/entityexample/person/iface/Person.java",
    "record.Person": "src/main/java/hr/hrg/hipster/entityexample/person/record/Person.java"
  }
}
```

The table is **not** repeated per document. Module-wide uniqueness is a property of the whole
indexed set, so it is computed once, after every emitter has run; a per-document table would
have to recompute the same uniqueness over its own subset and two documents could then
disagree about what an id means.

- `format` is the table's own version, an integer. A consumer that does not recognise it
  **MUST** refuse the table and say why — never guess. `1` is the only value in use.
- `module` and `sourceRoot` are diagnostics, so the file is self-describing when opened
  directly.
- `files` is id → path, sorted by id, so an unchanged tree is byte-identical pass to pass.

The index is a **directory of tables** rather than one addressing file, so the reserved tables
of § 8 can land without changing anyone's contract. `metadata/watch/<toolSet>/metadata.db`
(DEC-026 § 3) remains the *watch agent's* own cache and is **not** replaced by this directory.

Location rule: the index goes to `<nearest .jcodebuddy above the report directory>/index/`.
When the report directory is not inside a `.jcodebuddy/` at all (a temp directory in a test),
it goes to `<report dir>/index/` — which is why the `fileIndex` pointer is emitted rather than
assumed. Only an index that lives inside a real `.jcodebuddy/` gets a `README.md`; the
fallback location gets `files.json` and nothing else.

### 2. Ids are path-derived, module-relative, deterministic and cross-document stable

An `id` is the file's **simple name** — the extension and the `src/main/java/` prefix dropped —
qualified by the **shortest package suffix that disambiguates it** among all files the pass
indexed. `PersonSummary` stays bare; `Person` becomes `entity.Person`, `iface.Person` or
`record.Person` because all three exist in this repository, which is why a bare basename is not
enough.

The properties this buys, and why each matters:

| Property | Why |
| --- | --- |
| **unique per module** | a location resolves to exactly one file. Same package + same name = same file, so two ids can never collide |
| **deterministic** | the id is a function of the module-relative path plus the *set* of indexed paths; nothing depends on visit order or the clock |
| **identical in every document** | `Person.java` gets the same id in `Person.metadata.json` and in `Auditable.metadata.json`, so a consumer correlates documents without a shared registry |
| **compact** | 8–25 characters against 65–95 for a path, and the table is written once |
| **readable in a diff** | `entity.Person` in a metadata diff says what moved; a hash or an integer does not |

Paths are module-relative with forward slashes, `.java` included, never absolute, never `..`,
never project-relative.

**Known trade-off, recorded rather than hidden:** adding a file whose simple name collides with
an existing one may **lengthen the existing id** (`Person` → `entity.Person`). That change is
caused by a real new ambiguity and affects only that group. A content-independent short hash
would avoid it at the cost of readability; an integer index would be smallest and would renumber
on every insertion.

### 3. A source path appears exactly once, and a document contains none

Every module-relative path lives in `index/files.json`. No document, location, artifact or field
value contains a source path or a `.java` suffix; the only path-like value in a document is its
single `fileIndex` pointer, which points at the index and not at a source file. `sourcePath` was
replaced, not kept alongside the ids — nothing emits two spellings of the same fact:

| Before (DEC-027 amendment) | After |
| --- | --- |
| `markerSourcePath` (a path string) | `markerFile` (an id) + `markerLine` (an int) |
| `views[].sourcePath` | `views[].file` (an id); the declaration line stays `views[].lineNumber` |
| `properties[].sourcePath` | `properties[].file` (an id) |
| `allFields[].sourcePath` | `allFields[].file` (an id) |
| — | `views[].artifacts[]` (the artifact inventory, § 6) |
| — | `views[].fields[].at` (every location, § 5) |
| — | root `fileIndex` (the pointer to `index/files.json`, relative to the document) |
| — | `.jcodebuddy/index/files.json` — outside the document, one per module |

`properties[]` deliberately stays the "own declaration" record and does **not** gain a location
map: the view's `fields[].at` already holds the interface-side lines for every field, including
these. `allFields` gets `file` but deliberately **no** location map: it is a per-marker union,
and a union of per-view artifact ids has no stable meaning. The authoritative per-field location
map is `views[].fields[].at`; a consumer that wants "everywhere this field is" walks the
marker's views.

### 4. Every document points at the index with `fileIndex`

A document is no longer self-contained: a consumer needs the document and the table. Two
mitigations are mandatory rather than optional:

- each document carries `fileIndex` — the index path **relative to the document**, e.g.
  `"../../index/files.json"` — so nothing has to guess the `.jcodebuddy/` layout;
- a consumer that cannot read the index, or does not recognise its `format`, **MUST** fail
  loudly with a diagnostic rather than render a page of dangling ids. The renderer's kind is
  `html_index_missing`, in DEC-022's format.

The renderer resolves the table by **two routes** — the module root it already knows
(`<module>/.jcodebuddy/index/files.json`) and the pointer each document carries — and the
module-root route wins, so a wrong pointer cannot silently break the page while a moved index
still renders.

### 5. A field carries all its locations, grouped per artifact, with a fixed role vocabulary

Each view gains a `fields[]` array. A field's `at` map is keyed by **artifact id** (1–2
characters) and holds a `role → line` map inside that artifact:

```jsonc
{ "name": "age", "ordinal": 4,
  "type": { "type": "java.lang.Integer", "unboxed": "int", "primitive": true },
  "fieldKind": "DERIVED", "expression": "YEAR(NOW()) - YEAR(birthDate)",
  "at": { "0": { "accessor": 17, "annotation": 16 },
          "1": { "record-component": 30 },
          "3": { "enum-constant": 43, "name-slot": 98 },
          "4": { "accessor": 48, "field": 18, "ordinal-slot": 66 },
          "5": { "accessor": 49, "field": 32, "ordinal-slot": 58 } } }
```

Grouped rather than a flat list of `{artifact, role, file, line}` records: an artifact name is
nearly as long as a path (`PersonSummaryBuilderTracking` is 28 characters), so repeating it per
location would keep the payload large and lose the point of the table. Grouping also reads like
the artifact it describes.

**The role vocabulary is exactly these eight strings**, and the document writes them in this
order so two runs are byte-identical: `accessor`, `annotation`, `enum-constant`, `name-slot`,
`record-component`, `field`, `setter`, `ordinal-slot`.

| role | meaning |
| --- | --- |
| `accessor` | the no-argument read method (`Integer age();`), in a hand-written interface or a builder |
| `annotation` | the `@FieldSource` line that defines a `DERIVED`/`JOINED` field |
| `enum-constant` | the constant in `<View>_` — DEC-023's ordinal ledger position |
| `name-slot` | the `forName` arm (`case "age":`) in `<View>_` |
| `record-component` | a component of the record materialization |
| `field` | the stored field in a builder |
| `setter` | the fluent setter in a builder, or a `Write` method in a nested interface |
| `ordinal-slot` | the `case 3 ->` arm in a builder's `get(int)`/`set(int, Object)` |

A role that does not exist for a field is **absent**, not empty — a `DERIVED` field has no
`setter` anywhere, and a view that carries no record has no `record-component` for any field.
The page renders the absence.

`fields[]` is in **DEC-023 ledger order** (the order the emitters used); inside `at`, artifacts
appear in `artifacts` order and roles in the order above.

**Two role orders exist on purpose, and they differ.** The *document* writes the eight roles in
the order above, so two runs are byte-identical. The *page's* column order is the renderer's own
pre-existing constant — `accessor`, `annotation`, `enum-constant`, `record-component`, `setter`,
`field`, `ordinal-slot`, `name-slot` — because this change's non-goals forbid changing the
page's column set or its order. The renderer therefore iterates its own constant and never the
JSON's insertion order; neither list should be "fixed" to match the other.

### 6. Every view carries an artifact inventory

```jsonc
"artifacts": [
  { "id": 0, "name": "PersonSummary", "kind": "interface", "file": "PersonSummary", "line": 14,
    "generated": false, "own": true },
  { "id": 1, "name": "PersonSummary.Record", "kind": "record", "file": "PersonSummary", "line": 26,
    "generated": false, "own": true },
  { "id": 3, "name": "PersonSummary_", "kind": "enum", "file": "PersonSummary_", "line": 17,
    "generated": true, "own": true, "header": "Field metadata for the PersonSummary view." },
  { "id": 6, "name": "Person", "kind": "interface", "file": "entity.Person", "line": 14,
    "generated": false, "own": false }
]
```

- `id` — a small integer, unique within the view's artifact list, assigned in **reading order**:
  the view's own file first, then the nested types it declares, then the generated siblings in
  the order the pass emits them, then the foreign declaring interfaces in first-reference order.
  It is the key `fields[].at` uses, and it is a function of a deterministic artifact list.
- `name` — the display name the page prints (`PersonSummary`, `PersonSummary.Record`,
  `PersonSummaryBuilder`).
- `kind` — `interface` / `record` / `enum` / `class`.
- `file` — a **file id**, never a path.
- `line` — the declaration line of that type *inside* that file; a nested type has its own.
- `generated` — whether the file carries a DEC-021 header, i.e. whether the generator owns it.
  A hand-written nested record is an artifact of the view without being generated.
- `own` — the artifact is declared in this view's own file or was generated for it. **Foreign
  declaring interfaces** (`Person` for `PersonSummary.firstName`) are listed with `own: false`,
  so `fields[].at` needs no second key space; the rejected alternative was a separate
  `"foreign": {…}` map, which would double the shapes a consumer handles for no information
  gain.
- `header` — the DEC-021 description text, carried so a consumer does not re-read the file to
  label the artifact; omitted for a hand-written file.

Only the **view's own file** contributes its nested types as artifacts. A helper class nested
inside a *generated sibling* is not an artifact of the view.

**An artifact outside the module.** A generated artifact whose `--java-out` points outside the
module has no module-relative path and therefore no id: it is reported as a new
`artifact_outside_module` divergence and is **absent** from the inventory. A missing artifact is
honest; a path that cannot be resolved against the module is not.

### 7. The renderer verifies every link and no longer discovers

`scripts/entity-html/` reads the index, `views[].artifacts[]` and `views[].fields[].at` for its
whole model: an entity's marker, each view's artifacts, and each `(artifact, role) → line` cell.
Column order comes from the renderer's own role constant (§ 5), not from the JSON.

The source scan (`sources.js`) is kept **only to verify** a written link: the file must exist and
the line must still contain the member, and the `annotation` role is verified by `@FieldSource`
on that line instead. That is DEC-027 § 4.2, unchanged — a candidate that fails is dropped and
reported as `html_link_stale` and fails the run unless `--soft`. What is gone is discovery: no
artifact is found by naming convention, no member line is inferred from a line pattern.

A missing or unrecognised index is a loud `html_index_missing` error diagnostic and the renderer
renders nothing, because an id rendered as if it were a path is a page full of dead links that
looks like it worked. A document written **before this decision** — plain `sourcePath` strings,
no `artifacts`, no `fields` — still renders: every id key falls back to the path key it replaced
and the renderer uses its scan-based discovery path. That fallback is compatibility, not a
second supported path.

### 8. The Java model keeps paths; only the JSON uses ids. Reserved, not built

The conversion between paths and ids happens at the single point where JSON is written and read:
`toJson`/`fromJson`. The Java model is unchanged in meaning — `EntityMeta.markerSourcePath`,
`ViewMeta.sourcePath` and `Property.sourcePath` keep their existing semantics for every Java
caller and test, and `ArtifactMeta.file` is a **path** in the model and an **id** in the JSON.
The reason is structural: an id is a property of the whole indexed set, which is only complete
after every emitter has run, so an id cannot exist at the moment a location is extracted.

`fromJson(json)` without a table leaves ids **unresolved** (`null`) rather than inventing a path;
`fromJson(json, idToPath)` resolves them. `fromJson` also accepts `markerSourcePath`/`sourcePath`
when the id keys are absent, so a document written before this decision still parses.

**Reserved and explicitly not built** — the layout and its `format` version make room for these,
and nothing writes them today:

- **`hashes.json`** in the index directory: id → a hash of the file's **content** (CRLF
  normalised to LF first, so the same content is valid on any checkout), with a header naming
  the algorithm, the tooling revision and the flags that change output (`--packages`,
  `--adapters`, `--mapper`). It would let a watcher or an incremental pass decide what actually
  changed without re-reading and re-parsing the tree. It is never a correctness input: a
  missing, unreadable or version-mismatched table **MUST** force a full pass.
- **`artifacts[].inputs`** in a document: the dependency edges — per emitted artifact, the file
  ids it was generated *from*. It would turn the index into the graph an incremental pass needs
  instead of one it must re-derive by parsing.

Neither is specified further here, and **no hash algorithm was chosen and nothing was reused**
in this change. A checksum notion does exist in the tree — `project-automation`'s
`InMemoryMetadataCacheProvider` implements the watch2 `MetadataProvider` interface and tracks a
per-file `checksum` (`hasChanged(relPath, checksum)`, hashed with `MessageDigest`) — but it
belongs to the **watch agent's own cache** (DEC-026 § 3,
`metadata/watch/<toolSet>/metadata.db`), which this decision does not replace, and the tooling
**MUST NOT** depend on `project-automation` (`DependencyBoundaryTest`,
[DEC-W003 — Dev-time-only orchestrator boundary](../../../doc/architecture/decisions-watch/DEC-W003.md)). The choice
between sharing the watch agent's checksum and having the tooling own its own hash — which the
watcher would then consume from the index table — is deferred to whoever builds `hashes.json`,
and is to be recorded in this decision at that time. The same deferral applies to whether the
index ever consolidates with `metadata/watch/<toolSet>/metadata.db`.

### 9. Write ordering: artifacts → index → documents

The order inside a pass is now:

1. per marker, build `views` as before;
2. **per view, after every emitter has run for it**, collect the artifact files and extract the
   locations — an artifact inventory is only complete once the emitters have produced it;
3. after all markers, build and write the **index**, because an id cannot resolve before the
   table is complete;
4. then write each **document**, resolving paths to ids through the index.

The documents were previously written per marker, before the view loop; they are now the last
thing a pass writes. Three consequences are stated deliberately:

- A pass that fails half-way now writes **no** document, where previously it would already have
  written the documents of the markers it had reached.
- The run record (`--run-record`) is unaffected: it is written in a `finally`, so a failed pass
  is still recorded with `status: failed`.
- A view skipped by the `--packages` filter gets **empty** `artifacts`/`fields` lists: the
  metadata says what this pass produced, which is the honest answer for a filtered view.

A document that cannot resolve an id is a **bug**, not a fallback: the writer raises rather than
letting a path leak back into a document.

### 10. No content is ever recorded

Neither the record nor the report ever contains a file's text. The index holds a **path**, the
document holds an **id**, the page holds a path, a line and a role — never a copy of a Java
file. Copying a file's text would create a second, stale copy of a tree whose owner is the
committed source (`AGENTS.md` § 1), and it is unnecessary: a path plus a line is what opens the
file. A `.java` under `.jcodebuddy/` remains a mistake whatever wrote it (DEC-026 § 5), and a
report directory holds metadata only.

## Alternatives considered

- **A flat `[{artifact, role, file, line}]` location list.** Rejected: simpler to consume, but
  roughly 40 % larger because an artifact name is nearly as long as a path, which loses the
  point of the table. Grouping by artifact also reads like the thing it describes.
- **A table per document, or the table inlined in each document.** Rejected: module-wide
  uniqueness is a property of the whole set, so per-document tables can disagree about the same
  file; and one central table is the place a rename changes one row.
- **A hash id, or an integer index.** Rejected: a hash is the most stable and the most opaque,
  and an integer index is the smallest and renumbers on every insertion. The readable
  name-plus-suffix id is what makes a metadata diff say what moved (§ 2).
- **Keep `sourcePath` alongside the ids.** Rejected: two spellings of one fact is exactly the
  drift this change removes. Legacy *reading* is kept instead (§ 8).
- **A `"foreign": {…}` key space for a foreign declaring interface's locations.** Rejected: it
  doubles the shapes a consumer handles for no information gain; the artifact list is widened
  with `own: false` instead (§ 6).
- **A location map on `allFields` too.** Rejected: `allFields` is a per-marker union, so a union
  of per-view artifact ids has no stable meaning; the per-view maps are authoritative (§ 3).
- **Add `List<SourceLocation> locations` to `EntityFieldMeta`.** Offered by the plan and
  **dropped explicitly**: `allFields` deliberately has no location map, so nothing would consume
  it and it would be dead state in a mutable model.
- **A single `.jcodebuddy/index.json`, or the table under `metadata/`.** Rejected: a directory of
  tables is what gives the reserved content hashes a defined home without changing anyone's
  contract, and the index is not a report.
- **Keep DEC-027's render-time discovery and only shorten the paths.** Rejected: it leaves the
  answer a heuristic, leaves a second place where the same knowledge lives, and the measured
  defect (a truncated ledger from one line regex) is the symptom that motivated the change.
- **Let the renderer regenerate or re-scan when the index is missing.** Rejected: a stale table
  must be *detected* and said so, not silently worked around (§ 4).

## Consequences

- **One statement of a path, one stable handle, one place to grow.** A path is written once per
  module; a consumer cross-references an id instead of re-parsing a path it has already seen;
  and the index directory has a defined place for content hashes and dependency edges without a
  later layout change.
- **A document is no longer self-contained.** A consumer needs the document and the table, and
  the coupling reaches the track policy: `.jcodebuddy/index/` is derived and ignored by default
  like `metadata/`, but a project that opts its metadata subtree into git **must opt the index in
  too**, or its committed documents reference an uncommitted table (DEC-026's amendment).
- **The renderer reads the answer; it no longer infers it.** Its column set, labels, marker and
  view lines, descriptions, aspects and field order are unchanged. The measured page diff is
  exactly one class of change: the truncated ledger the old regex produced. Auditable's three
  views showed 1 field each instead of 3/5/5, and Person's `PersonUpdatableView`/`PersonUpdateForm`
  had `ordinal: null` plus a false `html_field_not_in_ledger` warning claiming `email`,
  `phoneNumber`, `firstName`, `lastName` were absent from an enum that declares exactly those
  constants at `PersonUpdatableView_.java` lines 25/32/39/46. After the change: fields 74 → 84,
  links 266 → 305, warnings 2 → 0, and `Divergences: 0 (0 metadata note(s))`.
- **`views[].properties[].lineNumber` and `fields[].at[...].accessor` are different facts and
  both are recorded.** `lineNumber` is still the declaration start, annotations included, while
  the accessor role is the accessor's **name-token** line — 16 vs 17 for `PersonSummary.age`.
  Neither is derived from the other.
- **`fields[].fieldKind` defaults to `"COLUMN"` for an unannotated accessor**, unchanged from the
  previous reading.
- **A failed pass writes no document** (§ 9). This is a real behaviour change, recorded here
  rather than discovered later; the run record still records the failure.
- **Size, measured honestly.** The three documents grew from 26 008 bytes
  (`Auditable` 2 473 / `PaymentMethod` 14 376 / `Person` 9 159) to 50 993 bytes (6 834 / 23 573 /
  20 586) — **1.96×** — plus `index/files.json` at 4 301 bytes and `index/README.md` at 2 699;
  `index.html` went from 284 674 to 307 376 bytes. That is **above the plan's estimate**: § 2.8
  guessed 25–30 KB in total and § 9.7 asked for under ~35 KB. The estimate omitted the artifact
  inventory (~7.7 KB) and under-costed the per-field entry — a type descriptor, the extra keys
  and the indentation around them. The counterfactual still holds and is why the shape was kept:
  a path written inline once per location, instead of one row per file plus a grouped `at` map,
  would be roughly 80 KB, so the grouped shape is what keeps this at about twice the old size
  rather than three times. § 4.10's stop condition ("if the JSON more than doubles, stop and
  re-examine the shape") was **not** triggered at 1.96×, and the shape is the one § 3 specifies.
  The budget assertion in `entity-html.test.js` is written to catch a *shape* regression rather
  than to police a byte.
- **One place, one writer.** Ids are assigned in `ModuleFileIndex`, locations are extracted in
  `MetadataLocations`, and `toJson`/`fromJson` are the only path↔id conversion point — so a
  consumer that finds an id it cannot resolve has found a bug, not a missing fallback.
- **Follow-up work has a home.** `hashes.json` and `artifacts[].inputs` are reserved with a
  stated shape but no implementation (§ 8); a watcher or incremental pass consumes them later
  without anyone's contract changing.
- **Negative:** the index directory is a new subfolder, so it needs its `README.md`, its track
  policy and its coupling note — a DEC-026 layout change, not just code (DEC-026's amendment).
- **The metadata is a strict superset of what the page renders, and that is deliberate.** The
  example records **315 locations** across 84 fields and 45 artifacts (by role: `name-slot` 88,
  `accessor` 88, `enum-constant` 84, `setter` 16, `field` 12, `ordinal-slot` 12,
  `record-component` 11, `annotation` 4). The page renders **305** of them. The 10 it does not
  are exactly the foreign declaring interface's `accessor` for a field whose view has no row in
  the marker-level `allFields` union: `PersonAuditable.firstName`/`.lastName` →
  `Person.java:15`/`:16`, `PersonAuditable.createdAt`/`.updatedAt` and
  `PaymentMethodAuditable.createdAt`/`.updatedAt` → `Auditable.java:8`/`:9`, and `type` on each
  of the four `*PaymentMethod` views → `PaymentMethod.java:29`. The cause is pre-existing and
  not introduced here: `allFields` is a per-marker union built with the **marker's own package**
  as lookup key, so for a view declared outside the marker's package (the `Auditable` marker
  lives in `example/`, its views in `person/entity/` and `paymentMethod/entity/`) that union
  holds only `id`. The page's "declared in" label and its view-aspect accessor cell derive from
  the metadata's declaration keys (`views[].properties[].file` / `allFields[].file`), so with no
  union row there is no declaring file and the cell is not rendered — exactly as before this
  change. Consuming the recorded foreign accessor instead would **add an `accessor` column to
  those six views**, and the page's column set, labels and link targets are frozen (§ Out of
  scope). The page therefore renders what its columns cover; widening the column set is left to
  a future change.
- **`html_field_not_in_ledger` is unchanged by this decision.** A field the metadata attributes
  to a view whose ledger has no constant for it is still shown without an ordinal and reported
  as a warning; the diagnostic kind and its severity are DEC-027's. On the committed example the
  warning no longer fires — not because the behaviour changed, but because the ledger is now read
  from what the pass recorded instead of guessed by a line regex (the page diff above).
- **Negative:** the writer still has no formatter behind it — `toJson` is a `StringBuilder` with
  an explicit comma discipline, so a mistaken insertion produces a JSON file only the tests
  reject.

## Out of scope

- **Source content, in any form.** Never (§ 10).
- **A repository-wide index.** The index is per module, beside the documents that reference it;
  a module-relative path in another module's table would mean nothing.
- **Building `hashes.json` or `artifacts[].inputs`** (§ 8). The layout reserves them; the
  contracts are not specified here.
- **Replacing `metadata/watch/<toolSet>/metadata.db`** with the index. The watcher's cache and
  the generator's inspectable record are different artifacts; consolidation is a later decision.
- **Mapper artifacts (`--mapper`) and their locations**, and adapter/binder artifacts beyond
  what `--adapters` actually emits.
- **Changing the page's link contract, its visual layout, or the roles and columns it renders.**
  Only the page's *inputs* changed. The metadata records more locations than the page shows
  (§ Consequences); widening the page's column set so it consumes them is a separate change,
  not this one.
- **Changing `Property.lineNumber` semantics, `allFields`' union semantics, or DEC-023's ordinal
  order.** The `allFields` union's package-keyed lookup — the cause of the 10 unrendered
  locations above — is likewise untouched.

## Acceptance criteria

1. A pass writes `<module>/.jcodebuddy/index/files.json` with its `format` (`1`), `module`,
   `sourceRoot` and a `files` table sorted by id, and writes it **once per pass, per module** —
   never at the repository root, never in another module's tree. *Asserted by*
   `MetadataFileIdsTest`.
2. **A source path is written once per module.** Every module-relative path lives in the index;
   no document, location, artifact or field value contains a source path or a `.java` suffix,
   and the only path-like value in a document is its `fileIndex` pointer. *Asserted by*
   `MetadataFileIdsTest`.
3. **Ids are unique, deterministic and cross-document stable.** Two passes produce identical
   index bytes; the same file has the same id in every document that mentions it; the
   disambiguation rule is exercised by `entity.Person` / `iface.Person` / `record.Person`; every
   `file` value used anywhere resolves in the index; and each document's `fileIndex` pointer
   resolves to that index. *Asserted by* `MetadataFileIdsTest`.
4. **Every field of every view carries all its locations**, for the roles that exist for it and
   none that do not (a `DERIVED` field has no `setter`). *Asserted by* `MetadataLocationsTest`.
5. **Every location is true**: the file exists and the line contains the member (`annotation` →
   `@FieldSource`). *Asserted by* the renderer's build-time check (a failure is `html_link_stale`
   and exits 1), by the bun test that re-checks every page link, and by the bun test that renders a
   document whose recorded line no longer holds the member and asserts the cell is dropped and
   reported as an error rather than written.
6. **The renderer discovers nothing from source.** With the index, `artifacts` and `fields`
   present, every page link maps back to a metadata location; a missing or unrecognised index is
   a loud `html_index_missing` error diagnostic and nothing is rendered; and a view a pass skipped
   (`--packages`) renders as a declaration with no columns, from its empty `artifacts`/`fields`
   rather than by falling back to the scan. *Asserted by* the bun tests in
   `scripts/entity-html/entity-html.test.js`.
7. **A pre-DEC-028 document still renders**, with no error-severity divergences. *Asserted by*
   the extended "stripped metadata" bun test and a `fromJson` legacy case.
8. **`.jcodebuddy/index/` holds `files.json` and `README.md` and nothing else** — the reserved
   tables are not implemented prematurely — and a pass creates the README when it is absent but
   **never overwrites** an existing one. *Asserted by* `IndexLayoutTest`.
9. **Nothing else regressed**: the tooling module is green with 324 tests, `bun test entity-html`
   reports 24 pass / 0 fail, `ExampleRegenerationTest` stays byte-identical (no generated `.java`
   changed), `GeneratorGuardTest` and `HtmlRenderBoundaryTest` stay green, no `.java` is under any
   `.jcodebuddy/`, and no source content appears anywhere.
10. **Documents updated**: this decision, the DEC-026 amendment, the decisions-index row and
    heading range, the `AGENTS.md` sentence, the tooling README section, the renderer README,
    `codebuddy.md` § 5.1, `.jcodebuddy/README.md` (layout + track policy),
    `.jcodebuddy/.gitignore` (the opt-in carries the index), the metadata README and the module's
    `context/entity-html-index.md`.
