## Context

`wyhash` was created inside this checkout on 2026-10-16 as a standalone package: one 64-bit hash, one definition,
and as many ports as this workspace needs (`fs-meta`'s two implementations are its Java and Bun consumers). The
Java implementation was moved into it from dia-log's `core` module and grew a `MemorySegment` input; the vectors
are generated from the reference (`std.hash.Wyhash`); and the JavaScript and Zig ports assert the same file.

**The same project already had a repository, and that repository is the published library.** `D:\wrk\java\wyhash`
— [github.com/hrgdavor/wyhash](https://github.com/hrgdavor/wyhash), MIT, `hr.hrg:wyhash:1.0.0` on Maven Central,
with its own release tooling (`central-publishing-maven-plugin`, sources and javadoc jars, GPG signing) — is the
project's real home, and the 241-line `Wyhash64.java` the merge started from was its `1.0.0`. Two homes for one
library is precisely the duplication this project exists to remove: the reason `wyhash` was created was that the
hash had been copied into several repositories and had begun to drift, and a copy living in this monorepo would
have been the next one.

**The measurement that made this a decision rather than a tidy-up.** The merge into the repository had to prove it
lost nothing, so it was checked before it was made: the repository's committed API (10 public members) is a
**subset** of the merged implementation's (35), and all three of its committed test classes' methods are present in
the incoming tests (`Wyhash64StreamingTest` grows 2 → 10). With that established, keeping both copies is keeping
one copy that is already behind — the merge added the reference's own acceptance vectors to the generator in the
repository and not in the checkout.

## Decision

**The repository is the home; this checkout consumes the artifact.**

1. **`wyhash/` is deleted from this checkout.** Java sources, tests, `pom.xml`, `conformance/`, `js/`, `zig/`,
   `tests.zig`, `check-ports.mjs`, `WYHASH.md`, `doc/zero-allocation.md` and `doc/adr/` all live in the
   repository, which is where the merge put them and where the next change to the hash belongs.
2. **Java consumers resolve `hr.hrg:wyhash`.** `fs-meta` keeps its declared dependency on
   `hr.hrg:wyhash:1.1.0-SNAPSHOT` (the merge of `1.0.0` with the evolved implementation), resolved from the local
   repository until `1.1.0` is published. Installing it is a **machine prerequisite, the same posture this
   repository already has for `@hrg/inject-examples` and for the artifacts under development**: run
   `mvn -o install -Dgpg.skip=true` once in the wyhash checkout. `mvn -pl :fs-meta` therefore no longer builds its
   own dependency, and `-am` no longer reaches it.
3. **Bun consumers resolve the JavaScript port through the package link.** The root `package.json` declares
   `"wyhash": "link:wyhash"`, so `fs-meta`'s Bun port imports `wyhash/js/wyhash64.mjs` from that checkout rather
   than from a copy in this tree — a junction, not a copy, which means an edit in the repository is visible here
   immediately. One-time setup: `bun link` inside the wyhash checkout, then `bun install` here. (`file:../wyhash`
   was tried first and is not usable: this Bun copies a `file:` package — including `.git` — and fails on a locked
   `.git/COMMIT_EDITMSG`; `files` in its manifest does not narrow that copy.)
4. **The recorded gate loses the module.** `wyhash` is removed from `GATE_MODULES` and from `GateContractTest`'s
   list; `fs-meta` stays. The gate builds what this repository owns, and the hash is not this repository's to
   build — a change to it is caught by that project's own `bun check-ports.mjs`, which is a stronger check than a
   member of this gate would be.
5. **AGENTS § 2's amendment stands, narrower.** Of the two packages that amendment named, `hr.hrg:fs-meta` is
   still in this checkout and still standalone by construction; `hr.hrg:wyhash` is now an ordinary external
   dependency, which a `watch/*` module may depend on for the same reason it always could: the rule was never
   about which directory a library lives in, and the watcher's checksum tables and this hash are one thing.
6. **The vectors remain the proof.** The move changes no value: `fs-meta/conformance/fsmeta-vectors.json`'s
   `hashCases` still pin them, and the repository's own generated vectors pin them against the reference. A
   consumer that pinned `1.0.0` gets the same values from `1.1.0`, so the merge is not a data migration.

**Consequence for the artifact's floor: Java 22.** The `MemorySegment` input cannot exist earlier
(`java.lang.foreign` is final in 22), so a consumer that pinned `1.0.0` for Java 18 must move to 22. That cost was
paid deliberately — the alternative was a hash library whose newest input kind exists in a fork.

## Consequences

- **Positive:** one home for one definition, with the project's own release and publishing; `fs-meta`'s Java and
  Bun ports hash with the *same code* (the artifact and the junction, respectively) instead of with the same
  algorithm as before this change; a change to the hash is one commit in one repository; the gate gets smaller and
  keeps only what this repository owns; and the hash's own checks (`bun check-ports.mjs`: reference integrity for
  both generated artefacts, and all three ports) live beside the code they check.
- **Negative:** this checkout gains a machine prerequisite (a local Maven install and a `bun link`) that a fresh
  clone does not have; `fs-meta` alone can no longer be built with `-pl :fs-meta` without that install; and the two
  repositories are now versioned and released separately, so a consumer that wants a newer hash follows that
  project's releases rather than this one's commits.
- **Not decided here:** what happens to the other copies in circulation — `hr.hrg:wyhash:1.0.0`, which
  `java-watch-core`'s `ChecksumDatabase` and `jcodebuddy-agent`'s `MetadataCache` still resolve, the copy vendored
  inside `jcodebuddy-core`, the jar under `watch/java-watch-run-sample/lib/`, and dia-log's own copy. Retiring them
  is a change in each of those places, against the same vectors; this decision only gives them one artifact to
  retire onto.
