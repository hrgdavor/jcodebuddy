# JetBrains change-type vectors, transcribed from MergeTest.kt via JETBRAINS_PORT.md 11.1
#
# WHY THIS FILE IS NOT A THREE_WAY_FIXTURES CASE, and the reason is that document's own rule 1:
# a fixture there is three COMPLETE, compilable Java files, because "a fragment cannot express a
# change" and type attribution needs a plausible source path. These vectors are text-fragment
# ranges with expected KINDS - they are about the ported text machinery (MergeRangeBuilder +
# MergeRangeUtil.getMergeType), not about a Java conflict type, and a whole-file fixture cannot
# state `y z | x y z | x y`. Forcing them into that layout would break the rule that makes those
# fixtures trustworthy, so they live here and JetBrainsParityGateTest reads them.
#
# Format, one vector per line, `|`-separated:
#   name | citation | left | base | right | expected
# `_` is a line separator, exactly as upstream writes it (so `x` is one line and `x_` is two).
# `expected` is `NONE` for no change, or a `;`-separated list of KIND:leftChanged:rightChanged,
# where the kinds are INSERTED, DELETED, MODIFIED and CONFLICT (1 = that side changed, 0 = it did not).
#
# The gate grades OUR classifier against this table and fails on any disagreement, so a line here
# is the benchmark's statement rather than ours - edit it only against upstream's source.
